课题一 · AI 方向

基于 RAG 与 LLM 的企业数据智能分类分级方案

用 AI 帮企业自动识别哪些数据是"敏感的"
🌍
研究背景：为什么要做这个？

想象一下，一家公司有几十万个数据表、几百万个字段——比如「手机号」「银行卡号」「员工工资」「产品价格」……国家要求企业必须知道自己有哪些敏感数据、每类数据要怎么保护。但靠人工一个个看，根本看不完！

😩
数据量太大，人工看不完
一个中型企业就有成千上万个数据字段，靠人工标注既慢又贵
📜
法规太复杂，记不住
《个人信息保护法》《数据安全法》条款繁多，不同数据有不同要求，普通员工很难精准判断
🔄
规则一直在变，维护成本高
法律法规不断更新，手动维护规则库非常繁琐，容易漏掉更新
💡 解决思路：让 AI 来读法规、学规则、自动判断——这就是这个课题要研究的！
🧩
核心概念：先搞懂这两个词
🧠
LLM（大语言模型）
就是 ChatGPT、文心一言、DeepSeek 这类 AI。
能理解人类语言，会"读文章"、"写答案"。

但有个问题：它不了解你们公司的内部规定，也可能"一本正经地胡说"（幻觉问题）。
🔍
RAG（检索增强生成）
先去"查资料"，再回答问题。
把相关的法规条文先找出来，塞给 AI 看，AI 再基于这些资料作判断。

效果：AI 有了"参考书"，回答更准确、有据可查。
🎯 类比理解：LLM 就像一个聪明但粗心的学生，RAG 就是考试前给他一份开卷资料——有了资料，答题更准！
📖
其他关键词速查
📊 数据分类
判断这条数据属于哪类，比如「手机号」→ 个人信息，「季度利润」→ 财务数据
🔐 数据分级
判断这条数据有多敏感，比如「公开 / 内部 / 敏感 / 核心」四个等级
🗄️ 向量数据库
一种特殊数据库，能根据"意思相近"来搜索，而不是靠关键词匹配。是 RAG 的核心工具
🔢 Embedding（向量化）
把文字转成一串数字（向量），让计算机能理解文字之间的"意思距离"
💬 Prompt 工程
设计"怎么问 AI"的艺术。同样的问题，不同问法效果差很多
✅ 测试集评估
准备一批已知答案的数据，测试 AI 判断对了几个，算出准确率
🎯
研究目标：要验证什么？
核心问题：RAG + LLM 这个组合，能不能帮企业自动判断数据的类别和敏感等级？和直接用 LLM 相比，准确率能提升多少？
1
建一个"法规知识库"
把《个人信息保护法》等法规内容整理好，存入向量数据库，让系统能快速检索相关条文
2
跑通核心流程
从"输入字段描述" → "检索相关规则" → "AI 给出判断+依据"，整个流程跑通
3
做实验、比效果
构建测试集，对比"有 RAG"和"没有 RAG"两种方案的准确率，用数据说话
⚙️

📄

方案设计 + 实验过程 + 准确率对比数据 + 结论，这是必须完成的
💻

能在浏览器里输入字段信息，点击按钮就能看到 AI 给出分类分级结果

立项材料参考提纲
研究目标
  • 验证 RAG+LLM 技术组合在企业数据分类分级场景中的技术可行性
  • 量化评估：与纯 LLM 方案相比，准确率能提升多少？
研究内容
  • 研究如何将法规文档处理成可检索的知识库（分块、向量化）
  • 设计 RAG 检索流程：怎么让检索结果更准确
  • Prompt 设计：怎样引导 AI 按格式输出结构化结果
  • 构建测试集，设计准确率等评估指标，做对比实验
技术路线
  • 数据准备：收集整理法规文档 → 文本分块 → Embedding 入库
  • 系统搭建：LangChain 搭建 RAG 流程 → 接入 LLM API
  • 实验评估：构建 50~100 条测试集 → 跑实验 → 统计准确率
  • 报告撰写：方案描述 + 实验结果 + 结论与不足

课题二 · 前端方向

轻量级数据资产可视化与合规性评估前端方案

用漂亮的图表，让人一眼看懂数据的分布和风险
🌍
研究背景：为什么要做可视化？

假设课题一帮企业把数据都分类分级好了——但结果是一堆数字和表格，管理层根本看不进去。他们需要的是：打开一个页面，直接看到"公司有哪些敏感数据、分布在哪、哪块风险最高"。

😵
数据表格太枯燥，决策层看不懂
一张张数据表没有直观感，不如一张图来得清晰
🐢
传统系统开发太慢
建完整的后端+数据库+前端，没几个月根本搞不定，但很多场景只需要一个演示原型
🤔
没有真实数据，没法做原型
项目初期拿不到真实数据，但还是需要一个可演示的效果来和客户/老板对需求
💡 解决思路：用 Mock 数据 + 现代前端框架，不依赖后端，快速做出高颜值、可交互的数据大屏原型！
🧩
核心概念速查
📦 数据资产
企业拥有的所有有价值的数据，比如用户数据、订单数据、财务数据等
🕸️ 数据血缘
数据从哪里来、经过哪些处理、流向哪里去，用有向图（箭头图）表示
🎭 Mock 数据
自己写的假数据，模拟真实情况，让前端页面有内容可以展示，不需要真实后端
🎨 高保真原型
长得和真实产品一模一样、可以点击交互的原型，而不是只有线框的草图
🔥 风险热力图
用颜色深浅表示风险高低，颜色越深风险越高，一眼就能找到问题所在
⚡ 前端框架
React 或 Vue，帮助你组织代码、构建交互界面，不用从零写 HTML/JS
🎯
研究目标：要探索什么？
核心问题：不搭后端、不连数据库，只用前端技术，能做出多好看、多好用的数据资产可视化系统？
1
选对可视化工具
对比 ECharts、D3.js、AntV G6 等图表库，找出适合数据资产场景的最优选择
2
做出核心图表
数据分级分布饼图、数据血缘关系图、风险热力图等，这些是数据资产平台的标配
3
探索无后端架构
用 Mock 数据模拟真实场景，打包后直接用浏览器打开就能跑，部署零成本
4
做好交互体验
点击图表可以下钻查看详情、筛选不同数据、图表之间联动响应
🖥️
系统有哪些页面？
🏠
数据资产总览
数据总量统计、各类数据占比饼图、敏感等级分布柱状图
🕸️
数据血缘关系图
用箭头连线展示数据表之间的依赖关系，可拖拽交互
⚠️
合规风险看板
风险热力图、高风险数据列表、合规评分雷达图
🔍
字段详情页
点进具体数据表，查看每个字段的分类分级标注和规则依据
🛠️

立项材料参考提纲
研究目标
  • 探索现代前端技术在企业数据资产可视化场景中的可行性与最佳实践
  • 构建不依赖后端的、可快速复用的数据资产可视化前端原型框架
研究内容
  • 数据资产可视化需求分析：哪些信息最关键、用什么图表最合适
  • 可视化库对比：ECharts / D3.js / AntV G6 各自的优缺点和适用场景
  • 无后端 Mock 数据方案设计：如何模拟真实的企业数据结构
  • 核心图表实现：分布图、血缘图、热力图的具体开发
  • 交互设计：下钻、筛选、多图表联动等体验优化
技术路线
  • 第一步：需求分析 → 画出页面结构草图
  • 第二步：Mock 数据建模 → 设计符合真实场景的 JSON 数据结构
  • 第三步：组件开发 → 先做单个图表，再拼成完整页面
  • 第四步：集成联调 → 确保图表联动、路由跳转正常
  • 第五步：效果演示 + 报告撰写
