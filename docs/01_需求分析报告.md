## 1. 项目背景

### 1.1 政策背景

国家"数据要素×三年行动计划（2024–2026）"明确要求推动数据资源的合规流通与价值创造。《数据安全法》《个人信息保护法》等法规对企业数据分类分级和敏感信息保护提出了强制性要求。

### 1.2 行业痛点

| 痛点 | 描述 |
|---|---|
| 结果不直观 | 分类分级完成后，结果以表格或数值呈现，管理层难以快速理解 |
| 开发周期长 | 传统可视化系统依赖完整后端，从立项到可演示往往需要数月 |
| 缺乏真实数据 | 项目初期无法获取企业真实数据，原型开发缺乏数据支撑 |
| 工具选型混乱 | 数据资产场景下，图表库选型缺乏系统化的评估和对比 |

### 1.3 项目定位

本项目属于整体企业数据资产治理平台的**前端子课题**，与课题一（AI 智能分类分级后端）互补，负责将分类分级结果以可视化方式呈现，最终可与后端打通形成完整的数据资产管理系统。

## 2. 用户需求分析

### 2.1 目标用户

| 用户角色 | 主要诉求 | 使用场景 |
|---|---|---|
| 企业管理层 | 一眼看懂数据资产整体状况和主要风险 | 日常汇报、决策支持 |
| 数据安全合规人员 | 定位高风险数据、追踪数据流转路径 | 合规审计、风险排查 |
| 数据资产管理员 | 浏览和检索具体数据表和字段的分类标注 | 日常数据治理工作 |
| 研究人员 / 演示者 | 快速搭出可演示的高保真原型 | 项目汇报、需求对齐 |

### 2.2 核心用户故事

1. 作为**管理层**，我希望打开一个页面就能看到公司数据资产的整体分布，了解敏感数据占比和最高风险区域，以便快速掌握全局。
2. 作为**合规人员**，我希望能通过风险看板一眼定位高风险数据表，并可点击查看详细字段信息和法规依据，以便开展合规审计。
3. 作为**数据管理员**，我希望能通过血缘图追踪特定数据表的上下游依赖，了解数据流向，以便评估变更影响。
4. 作为**演示者**，我希望系统无需连接后端也能流畅运行，打包后可直接在浏览器打开，以便随时向客户/导师演示。

## 3. 功能需求

### 3.1 功能模块总览

```
系统功能模块
├── F1 数据资产总览页
│   ├── F1.1 数据资产统计概要（总量、各类别数量、覆盖业务域）
│   ├── F1.2 分类分布饼图（个人信息 / 财务 / 业务 / 公开等）
│   ├── F1.3 敏感等级分布柱状图（核心 / 敏感 / 内部 / 公开）
│   └── F1.4 数据资产趋势折线图（近期新增/变更数量）
├── F2 数据血缘关系图页
│   ├── F2.1 有向关系图（节点=数据表，边=数据流转关系）
│   ├── F2.2 节点可拖拽与缩放
│   ├── F2.3 点击节点展示表详情侧边栏
│   └── F2.4 按业务域 / 敏感等级筛选过滤
├── F3 合规风险看板页
│   ├── F3.1 风险热力图（按业务域×等级维度展示密度）
│   ├── F3.2 高风险数据列表（按风险分排序，支持翻页）
│   ├── F3.3 合规评分雷达图（覆盖个人信息/财务/业务等维度）
│   └── F3.4 法规合规状态统计（已合规/待整改/超期）
└── F4 字段详情页
    ├── F4.1 数据表基本信息（名称、所属业务域、负责人）
    ├── F4.2 字段列表（含分类、等级、法规依据）
    ├── F4.3 字段级风险标注（高亮显示高风险字段）
    └── F4.4 返回/面包屑导航
```

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|---|---|
| 首屏加载时间 | ≤ 3 秒（本地文件打开） |
| 图表渲染时间 | 单图表渲染 ≤ 500ms |
| 血缘图节点数 | 支持至少 50 个节点流畅渲染 |
| 响应式适配 | 支持 1280×720 及以上分辨率正常展示 |

### 4.2 可用性需求

- 系统打包为静态文件，无需服务器或数据库，浏览器直接打开即可运行
- 所有图表提供图例说明，关键指标提供 Tooltip 悬停说明
- 页面提供清晰的导航结构，用户可在 3 次点击内到达任意目标页面

### 4.3 可维护性需求

- Mock 数据与组件逻辑分离，存放于独立 JSON 文件，便于后期替换为真实 API
- 图表组件应封装为可复用单元，方便后续扩展新页面
- 代码结构清晰，关键实现提供必要注释

### 4.4 兼容性需求

- 支持主流现代浏览器（Chrome 90+、Firefox 88+、Edge 90+）
- 无需 Node.js 运行时，直接用浏览器打开 index.html 可运行（或提供简单的 `npm run dev` 启动方式）

## 5. 约束条件

| 约束类别 | 说明 |
|---|---|
| 技术约束 | 不依赖后端服务，所有数据来自本地 Mock JSON 文件 |
| 时间约束 | 第一阶段（前期准备）需完成需求分析与技术路线确定 |
| 数据约束 | 当前使用 Mock 数据，不涉及真实企业敏感信息 |
| 团队约束 | 团队成员具备基础前端开发能力，对复杂血缘可视化经验不足 |
