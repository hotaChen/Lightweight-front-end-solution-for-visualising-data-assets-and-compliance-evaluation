# 部署说明

本文说明数据资产分类分级与合规风险管理平台的运行模式、环境变量、构建与部署方式。

## 一、运行模式

前端页面统一通过 `GET /api/platform` 读取数据，数据源有三种模式：

| 模式 | 数据来源 | 适用场景 |
|------|----------|----------|
| Mock 模式 | `mock/platform.json`（Vite 内置中间件） | 无需数据库，快速界面演示 |
| SQLite 模式 | 本地 `server/index.mjs` + SQLite | 本地开发、可扩充数据规模 |
| 生产模式 | 真实后端（按 `API_CONTRACT.md` 契约） | 正式部署 |

- `VITE_ENABLE_MOCK_API=true`：启用 Mock 模式，`/api` 请求由 Vite 直接返回静态 JSON。
- `VITE_ENABLE_MOCK_API=false`（默认）：`/api` 走真实服务（开发期代理到 `http://localhost:8787`，生产期代理到 `VITE_API_BASE_URL`）。

## 二、环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `VITE_ENABLE_MOCK_API` | `false` | 是否启用内置 Mock API |
| `VITE_API_BASE_URL` | `/api` | 前端请求数据服务的基础路径 |
| `VITE_BASE` | `/` | 站点子路径（部署到子目录时设置） |
| `API_PORT` | `8787` | SQLite API 服务端口（`server/index.mjs`） |
| `DATABASE_PATH` | `db/platform.sqlite` | SQLite 数据库文件绝对路径 |
| `CORS_ORIGIN` | `*` | 允许的跨域来源（正式部署应设为前端域名） |

## 三、本地开发

```bash
npm install

# 方式 A：Mock 模式（无需数据库）
npm run dev:mock          # 或 VITE_ENABLE_MOCK_API=true npm run dev

# 方式 B：SQLite 模式
npm run db:init           # 首次运行：初始化数据库并从 mock/platform.json 导入
npm run api               # 启动数据 API（http://localhost:8787）
npm run dev               # 另开终端启动前端（代理 /api → 8787）
```

> SQLite 模式依赖系统安装 `sqlite3` 命令行工具（Windows/Linux/macOS 均需）。

## 四、生产构建与部署

```bash
npm run build             # 生成 dist/（含 vue-tsc 类型检查 + vite 构建）
npm run preview           # 本地预览构建产物
```

生产部署需同时提供「静态前端」和「数据 API」两部分：

1. **静态托管**：将 `dist/` 交给任意静态服务器（Nginx、对象存储、CDN 等）。
2. **数据 API**：启动 `node server/index.mjs`（或替换为真实后端，遵循 `API_CONTRACT.md`）。
3. **反向代理**：将前端同源的 `/api` 请求转发到数据 API，或通过 `VITE_API_BASE_URL` 指向后端域名。

### Nginx 反代示例（同源）

```nginx
server {
    listen 80;
    server_name example.com;
    root /var/www/platform/dist;
    index index.html;

    # SPA 路由回退到 index.html（history 模式必需）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 数据 API 转发
    location /api/ {
        proxy_pass http://127.0.0.1:8787;
    }
}
```

### 跨域部署

若前后端不同源，构建前配置 `.env.production`：

```env
VITE_API_BASE_URL=https://your-backend.example.com/api
VITE_ENABLE_MOCK_API=false
```

并在后端开启对应前端来源的 CORS（`CORS_ORIGIN=https://your-frontend.example.com`）。

## 五、子路径部署

部署到子目录（如 `https://example.com/platform/`）时：

```env
VITE_BASE=/platform/
```

重新构建后，`dist/` 内资源与路由 `base` 会统一为 `/platform/`，Nginx 的 `try_files` 回退无需改动。

## 六、路由守卫与异常页

- **兜底 404**：未匹配路径统一进入 `NotFound` 页（`/:pathMatch(.*)*`）。
- **参数校验**：`/catalog/:id` 在数据就绪后校验 ID，无效则重定向到 `/catalog`。
- **权限门禁**：路由 `meta.roles` 声明可访问角色，当前角色不匹配则重定向 `/403`。
- **文档标题**：`router.beforeEach` 依据 `meta.title` 更新 `document.title`。

### 角色说明（演示级）

角色存储在 `localStorage` 键 `platform_role`，取值 `VIEWER`（默认）/ `ADMIN`。

```js
localStorage.setItem('platform_role', 'ADMIN')   // 切换为管理员
localStorage.removeItem('platform_role')          // 恢复默认 VIEWER
```

为某条路由启用权限，只需在路由声明中加 `meta.roles`：

```ts
{ path: '/admin', component: AdminPage, meta: { title: '管理', roles: ['ADMIN'] } }
```

## 七、常见问题

- **`dist/index.html` 双击打开后停在「数据加载失败」**：生产构建不内置数据源，需按第四节启动数据 API 并反代 `/api`，或使用 Mock 模式的开发服务器。
- **`sqlite3` 未找到**：安装 SQLite 命令行工具，或改用 Mock 模式开发。
- **数据库结构变更后数据未刷新**：删除 `db/*.sqlite` 后重新 `npm run db:init`（当前无自动迁移）。
