# 技术选型调研报告

**项目名称**：轻量级数据资产可视化与合规性评估前端方案  
**版本**：v1.0  
**日期**：2026-05-12

---

## 1. 调研范围概述

本报告围绕**前端框架**、**数据可视化库**（通用图表 + 关系图）、**UI 组件库**、**Mock 数据方案**四个维度展开调研，结合项目"无后端、高保真、快速开发"的核心约束，给出推荐选型。

---

## 2. 前端框架选型

### 2.1 候选方案

| 方案 | 描述 |
|---|---|
| 原生 HTML + JS | 不引入任何框架，直接操作 DOM |
| React 18 | Meta 出品的主流前端框架，组件化、生态丰富 |
| Vue 3 | 渐进式框架，学习曲线平缓，国内生态活跃 |

### 2.2 对比分析

| 维度 | 原生 HTML/JS | React 18 | Vue 3 |
|---|---|---|---|
| 上手难度 | 低 | 中 | 低~中 |
| 组件化能力 | 无 | 强 | 强 |
| 状态管理 | 手动维护 | useState/Redux | reactive/Pinia |
| 图表联动支持 | 繁琐 | 自然（状态驱动） | 自然（响应式驱动） |
| 构建打包 | 无需 | Vite/Webpack | Vite |
| 中文文档 | 充足 | 充足 | 充足 |
| 团队适配性 | 高（入门快） | 中（JSX 有门槛） | 高（模板语法友好） |
| 静态部署 | 直接打开 html | npm build 后静态部署 | npm build 后静态部署 |

### 2.3 结论

**推荐：Vue 3 + Vite**

理由：
- Vue 3 的 Composition API 与响应式系统对于"多图表联动"场景非常契合，数据变化自动驱动视图更新；
- Vite 开发体验极佳（热更新 < 100ms），构建产物为纯静态文件，打包后直接用浏览器打开；
- 与 AntV G6（血缘图）、ECharts 的集成生态完善，中文文档质量高；
- 团队成员若有 HTML/JS 基础，Vue 的模板语法上手成本最低。

若团队 React 经验更丰富，React 18 亦可替代，整体差异不大。

## 3. 数据可视化库选型（通用图表）

### 3.1 候选方案

| 库 | 来源 | GitHub Stars | 许可证 |
|---|---|---|---|
| ECharts 5 | Apache / 百度 | ~60k | Apache 2.0 |
| AntV G2 | 蚂蚁集团 | ~12k | MIT |
| D3.js v7 | Observable | ~108k | ISC |
| Chart.js | 社区 | ~64k | MIT |

### 3.2 对比分析

| 维度 | ECharts 5 | AntV G2 | D3.js | Chart.js |
|---|---|---|---|---|
| 适用图表类型 | 饼/柱/线/热力/雷达等，全面 | 同 ECharts，更偏统计分析 | 几乎无限制，需手写 | 饼/柱/线，偏简单 |
| 学习成本 | 低（配置项驱动） | 中（有 API 设计变化） | 高（需掌握 SVG/D3 概念） | 低 |
| 热力图支持 | 原生支持（visualMap 组件） | 支持 | 需自行实现 | 不支持 |
| 雷达图支持 | 原生支持 | 支持 | 需自行实现 | 支持 |
| 中文文档质量 | 极佳 | 良好 | 一般（以英文为主） | 良好 |
| 与 Vue 集成 | 成熟（vue-echarts） | 成熟 | 手动集成 | 成熟 |
| CDN 引入 | 支持 | 不推荐 | 支持 | 支持 |
| Bundle 大小 | 按需引入可控（~300KB） | 按需约 400KB | ~300KB | ~200KB |

### 3.3 结论

**推荐：Apache ECharts 5**

理由：
- 项目所需图表类型（饼图、柱状图、折线图、热力图、雷达图）ECharts 均原生支持，零额外开发量；
- 配置项驱动的开发模式与 Vue 的响应式结合极为简洁；
- 中文文档最完善，官方示例覆盖全部用例；
- `vue-echarts` 封装成熟，可直接作为 Vue 组件使用。

## 4. 数据可视化库选型（关系图 / 血缘图）

### 4.1 候选方案

| 库 | 描述 |
|---|---|
| AntV G6 5.x | 蚂蚁集团的专业图分析库，专门面向关系图场景 |
| ECharts Graph | ECharts 内置的 graph 系列 |
| D3-Force | D3 的力导向布局，高度定制 |
| Cytoscape.js | 专业图形库，生物信息学起源，通用性强 |
| Vis.js Network | 轻量级网络图库 |

### 4.2 对比分析

| 维度 | AntV G6 | ECharts Graph | D3-Force | Cytoscape.js | Vis.js |
|---|---|---|---|---|---|
| 专业程度 | 极高（专为关系图设计） | 中（通用图表附带） | 高（需大量自定义） | 高 | 中 |
| 拖拽交互 | 原生支持 | 有限支持 | 需手动实现 | 原生支持 | 原生支持 |
| 缩放/平移 | 原生支持 | 有限 | 需手动实现 | 原生支持 | 原生支持 |
| 血缘图布局 | 内置 Dagre 层次布局 | 无 | 力导向 | 多种布局 | 力导向 |
| 节点自定义 | 极强 | 一般 | 极强（需写 SVG） | 强 | 一般 |
| 学习成本 | 中 | 低 | 高 | 中 | 低 |
| 中文文档 | 完善 | 完善 | 一般 | 一般 | 一般 |

### 4.3 结论

**推荐：AntV G6 5.x**

理由：
- G6 专为有向关系图、DAG（有向无环图）场景设计，内置 Dagre 布局完美适配数据血缘的上下游层次展示；
- 原生支持节点拖拽、画布缩放平移、节点高亮、边动画等交互，无需额外开发；
- 提供"点击节点展开详情"等通用交互模式的内置 API；
- 蚂蚁集团在金融、数据治理场景大量使用，成熟度有保障。

## 5. UI 组件库选型

### 5.1 候选方案

| 库 | 框架 | 描述 |
|---|---|---|
| Ant Design Vue (antdv) | Vue 3 | Ant Design 的 Vue 3 实现，企业级组件库 |
| Element Plus | Vue 3 | 饿了么出品，国内最常用的 Vue UI 库 |
| Naive UI | Vue 3 | 国产，TypeScript 优先，性能好 |
| Arco Design Vue | Vue 3 | 字节跳动出品，设计语言现代 |

### 5.2 对比分析

| 维度 | Ant Design Vue | Element Plus | Naive UI | Arco Design Vue |
|---|---|---|---|---|
| 组件丰富度 | 极丰富 | 丰富 | 丰富 | 丰富 |
| 数据表格 | Table（功能强，支持排序/筛选/固定列） | Table | DataTable | Table |
| 深色主题 | 支持 | 支持（v2.2+） | 完善 | 支持 |
| 企业级风格 | 是（Ant Design 规范） | 中性 | 中性 | 是（字节风格） |
| 文档质量 | 极佳 | 极佳 | 良好 | 良好 |
| 与 ECharts 集成 | 无冲突 | 无冲突 | 无冲突 | 无冲突 |

### 5.3 结论

**推荐：Ant Design Vue 4.x（antdv）**

理由：
- 数据资产管理系统是典型的**企业级数据平台**场景，Ant Design 的设计规范和组件能力（Table、Statistic、Breadcrumb、Drawer、Tabs）高度贴合；
- 企业导师背景（合合信息）习惯于 Ant Design 生态，汇报演示时视觉风格更专业；
- Table 组件的内置排序、筛选、固定列能力直接满足字段详情页需求，无需额外开发。

## 6. Mock 数据方案选型

### 6.1 候选方案

| 方案 | 描述 |
|---|---|
| 静态 JSON 文件 | 手写 JSON，import 到组件中使用 |
| Mock.js | 运行时随机生成 Mock 数据 |
| Faker.js | 生成符合真实格式的假数据（手机号、姓名等） |
| MSW（Mock Service Worker） | 拦截真实 HTTP 请求，返回 Mock 数据 |

### 6.2 对比分析

| 维度 | 静态 JSON | Mock.js | Faker.js | MSW |
|---|---|---|---|---|
| 数据可控性 | 极高（手写确定内容） | 低（随机生成） | 中 | 高 |
| 与真实 API 切换 | 需改 import | 需改 | 需改 | 几乎无缝（只改配置） |
| 可读性 | 高 | 低 | 中 | 中 |
| 学习成本 | 极低 | 低 | 低 | 中 |
| 演示适配性 | 极高（演示内容固定） | 低（每次不同） | 中 | 高 |
| 无需 Node 运行 | 是 | 是 | 是 | 否（需 Service Worker） |

### 6.3 结论

**推荐：静态 JSON 文件 + 少量 Faker.js 辅助生成**

理由：
- 演示场景下数据内容需固定、有业务意义，静态 JSON 最直接；
- Mock 数据与业务逻辑分离，存放于 `src/mock/` 目录，后期接入真实 API 只需修改数据获取层；
- 用 Faker.js 辅助批量生成字段列表等数量较大的列表数据，减少手写工作量。

## 7. 开发工具与工程化方案

| 类别 | 推荐工具 | 说明 |
|---|---|---|
| 构建工具 | Vite 5 | 极速热更新，零配置 Vue 支持，build 产物为纯静态文件 |
| 包管理 | npm / pnpm | pnpm 速度更快，推荐使用 |
| 代码风格 | ESLint + Prettier | 保持代码一致性 |
| IDE | VS Code + Volar 插件 | Vue 3 官方推荐的 IDE 方案 |
| 版本控制 | Git + GitHub | 代码托管与协作 |
| 路由 | Vue Router 4 | 官方路由，支持 Hash 模式（无需服务器配置） |

**关键配置**：Vue Router 使用 `createWebHashHistory`（Hash 模式），使得构建产物中 `index.html` 直接双击打开即可运行，无需 Web 服务器。

## 9. 风险与应对

| 风险 | 说明 | 应对措施 |
|---|---|---|
| G6 学习曲线 | G6 5.x API 与 4.x 有较大变化，文档不够稳定 | 优先参考 G6 官方 Demo，遇到问题降级使用 ECharts Graph 作为备选 |
| 性能瓶颈 | 血缘图节点过多时渲染卡顿 | Mock 数据控制在 30-50 节点，足够演示 |
| 版本兼容 | Ant Design Vue 4.x 要求 Vue 3.2+ | 统一使用 Vue 3.4+ 确保兼容 |
| 静态部署路径 | Hash 路由在某些环境下跳转异常 | 全程使用 Hash 模式，避免 History 模式的路径问题 |
