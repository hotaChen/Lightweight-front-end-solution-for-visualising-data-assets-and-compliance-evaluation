# 本地联调启动与当前进度

> 最后更新：2026 年 10 月 15 日  
> 适用环境：Windows + WSL，前端工程位于 `/mnt/d/cxcy`，RAG 工程位于 `/mnt/d/RAG_PROJECT`

## 一、服务与端口

| 服务 | 工程目录 | 默认地址 | 用途 |
|---|---|---|---|
| Vue/Vite 前端 | `/mnt/d/cxcy` | `http://127.0.0.1:5173/` | 平台页面及 RAG 页面 |
| SQLite 数据 API | `/mnt/d/cxcy` | `http://127.0.0.1:8787/api/platform` | 总览、血缘、风险和资产目录数据 |
| RAG FastAPI | `/mnt/d/RAG_PROJECT` | `http://127.0.0.1:8000/api/health` | 单字段分类、批量任务、结果及依据查询 |

Vite 开发服务器会自动代理两类请求：

- `/api/*` → `http://localhost:8787/api/*`
- `/rag-api/*` → `http://127.0.0.1:8000/api/*`

## 二、推荐启动顺序

三个服务需要分别占用一个持续运行的终端。不要使用会在命令结束后回收后台进程的一次性 shell；推荐直接保持三个终端窗口运行。

### 1. 启动 SQLite 数据 API

首次运行或数据库文件被删除后，先初始化数据库：

```bash
cd /mnt/d/cxcy
npm run db:init
```

日常启动：

```bash
cd /mnt/d/cxcy
npm run api
```

正常日志：

```text
数据 API 已启动：http://localhost:8787/api/platform
```

### 2. 启动 RAG 服务

#### 当前会话中的已验证启动命令

2026 年 10 月 15 日当前运行环境使用 `/tmp` 下的临时 Python 环境和 `safetensors` 模型副本：

```bash
cd /mnt/d/RAG_PROJECT
EMBEDDING_MODEL_PATH=/tmp/cxcy-bge-base-zh-v1.5 \
```

正常日志：

```text

Uvicorn running on http://127.0.0.1:8000
```

#### 机器重启或 `/tmp` 被清理后的恢复

当前 RAG 项目原有 `.venv` 不完整，且未固定依赖版本。直接安装最新 `transformers` 后，会因为本地模型使用 `pytorch_model.bin`、当前 Torch 为 2.5.1 而拒绝加载。因此在正式修复依赖前，按以下步骤恢复已验证的临时环境。

1. 创建临时虚拟环境并安装依赖：

```bash
rm -rf /tmp/cxcy-rag-venv
/home/wjq/miniconda3/envs/torch/bin/python3.10 \
  -m venv --system-site-packages /tmp/cxcy-rag-venv
/tmp/cxcy-rag-venv/bin/python \
  -m pip install -r /mnt/d/RAG_PROJECT/requirements.txt
```

2. 将可信的本地模型转换为临时 `safetensors` 副本：

```bash
rm -rf /tmp/cxcy-bge-base-zh-v1.5
mkdir -p /tmp/cxcy-bge-base-zh-v1.5

find /mnt/d/RAG_PROJECT/.runtime/models/bge-base-zh-v1.5 \
  -maxdepth 1 -type f ! -name 'pytorch_model.bin' \
  -exec ln -s {} /tmp/cxcy-bge-base-zh-v1.5/ \;

/tmp/cxcy-rag-venv/bin/python - <<'PY'
from pathlib import Path

import torch
from safetensors.torch import save_file

source = Path('/mnt/d/RAG_PROJECT/.runtime/models/bge-base-zh-v1.5/pytorch_model.bin')
target = Path('/tmp/cxcy-bge-base-zh-v1.5/model.safetensors')
state = torch.load(source, map_location='cpu', weights_only=True)
save_file(state, target, metadata={'format': 'pt'})
PY
```

3. 为当前 `sentence-transformers` 写入兼容的池化配置：

```bash
mkdir -p \
  /tmp/cxcy-bge-base-zh-v1.5/1_Pooling \
  /tmp/cxcy-bge-base-zh-v1.5/2_Normalize

cat > /tmp/cxcy-bge-base-zh-v1.5/1_Pooling/config.json <<'JSON'
{
  "embedding_dimension": 768,
  "pooling_mode": "cls",
  "include_prompt": true
}
JSON

cat > /tmp/cxcy-bge-base-zh-v1.5/2_Normalize/config.json <<'JSON'
{
  "module_input_name": "sentence_embedding",
  "module_output_name": "sentence_embedding"
}
JSON
```

4. 使用上一节的“当前会话中的已验证启动命令”启动 RAG。

> 后续应将该临时方案替换为稳定的 Linux 文件系统虚拟环境，并在 `requirements.txt` 中固定兼容版本；不要长期依赖 `/tmp`。

## 四、停止服务

优先在三个运行终端中分别按 `Ctrl+C`。如果终端已丢失，可先确认进程后再结束：

```bash
ss -ltnp | grep -E ':(5173|8787|8000) '
```

不要直接使用宽泛的 `pkill node` 或 `pkill python`，以免误停其他项目。

## 六、常见故障

### `listen EPERM` 或端口无法监听

如果在受限沙箱中启动服务，Node 或 Python 可能因无权监听端口而报错。应在普通 WSL 终端运行上述启动命令。

### 前端显示“数据加载失败”

确认 `npm run api` 正在运行，并检查：

```bash
curl http://127.0.0.1:8787/api/platform
```

### 前端显示“RAG 服务离线”

依次检查：

```bash
curl http://127.0.0.1:8000/api/health
curl http://127.0.0.1:5173/rag-api/health
```

第一条失败表示 RAG 服务未启动或启动失败；第一条成功、第二条失败则检查 `vite.config.ts` 中的 RAG 代理配置。

### RAG 报 Torch 版本或 `Pooling.__init__` 错误

说明使用了最新未锁定依赖直接加载旧格式模型。按第二节恢复临时环境及 `safetensors` 模型副本，不要直接使用当前不完整的 `/mnt/d/RAG_PROJECT/.venv`。
