## 一、阶段目标

近期工作重点是完善平台基础工程能力，并将 RAG 数据分类后端接入现有可视化平台，形成“字段输入—知识检索—模型判断—结果与依据展示”的完整演示链路。

## 二、近期完成内容

### 1. 平台基础能力完善

- 完善全局导航和系统说明页，统一总览、血缘、风险、资产目录和 RAG 分类入口。
- 增加路由守卫、动态页面标题、字段详情参数校验及 403/404 异常页面。
- 增加 `VIEWER` / `ADMIN` 演示角色及基础权限门禁。
- 支持 Mock、SQLite 和真实后端三种数据运行模式。
- 完善子路径部署、开发代理、环境变量示例和生产部署说明。
- 修复 `dev:mock` 跨平台兼容问题，并同步更新 README。

### 2. RAG 智能分类前端接入

新增 `/rag` 页面及独立 API 封装，当前页面包含以下能力：

- **单字段分类**：录入字段名、中文名、类型、业务域、字段注释和样例值。
- **数据库批量分类**：选择或手工填写数据表，设置采样数量和失败处理策略。
- **任务结果查询**：按任务、库表字段、分类等级、个人信息和待复核状态筛选。
- **法规依据查看**：展示分类结果、置信度、判断理由、决策路径和知识库检索片段。
- **服务状态检查**：页面可识别 RAG 后端在线、离线及接口异常状态。
- **独立代理配置**：RAG 使用 `/rag-api`，平台数据接口继续使用 `/api`，互不影响。

## 三、当前可演示成果

会议中可以重点演示以下流程：

1. 从平台侧边栏进入“RAG 智能分类”。
2. 查看 RAG 服务在线状态。

## 四、当前问题与风险

### 1. MySQL 环境未运行

当前 Windows 主机未检测到 MySQL/MariaDB 服务或进程，`3306`、`3307` 端口均未监听。因此：

- 单字段 RAG 分类可以正常使用；
- A 库表清单暂时无法加载；
- 数据库批量分类、任务历史和持久化结果查询暂时无法进行真实联调。

### 2. 运行环境仍是开发形态

- Python 运行环境当前位于临时目录，机器重启或临时目录清理后可能需要恢复。
- DeepSeek、数据库等敏感配置仍需通过本地 `.env` 管理，禁止提交到 Git。
- 前端现有 ECharts/G6 页面构建包较大，生产部署前仍需进一步拆包优化。

### 3. 批量任务能力仍需增强

- 当前数据库任务为同步执行，暂不支持实时字段级进度。
- 尚未完成任务取消、失败重试和断点续跑。
- 人工复核和修改后的结果回写流程尚未形成闭环。
